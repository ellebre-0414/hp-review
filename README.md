# TWIY法律事務所 サイトの使い方

## 制作の参考記録

参考サイトの分析とユーザーの評価は [DESIGN_REFERENCES.md](DESIGN_REFERENCES.md) に蓄積しています。デザインや構成を検討するときに参照してください。

## TWIY塾サイトとの相互リンク

法律事務所の公開用10ページ（ブログ一覧・記事ページを含む）と、塾・ブランド側の現行４ページの下部に共通の「TWIY LINKS」があります。現在閲覧中のサイト自身へのリンクは省き、ほかの２サイトだけを同じ大きさで並べます。塾ホーム・VOICEではブランドと法律事務所、ブランド・購入ページでは塾と法律事務所、法律事務所の各ページでは塾とブランドを表示します。PCでは横２列、スマートフォンでは縦１列です。塾・ブランドのリンク先は、隣の `TWIY BRAND HP/site/01_current/` 内の `index.html` と `brand.html` です。同じタブ内で移動します。

2026年9月21日のご指定により、塾サイト・ブランドサイトは①現行案に一本化しています。②③は `TWIY BRAND HP/archive/2026-09-21_retired-designs/` に保存し、今後の編集対象にはしません。①のフォルダーの位置は変更していません。

現在は２つのプロジェクトを同じ親フォルダーに置いたローカル確認用のリンクです。公開時には、それぞれの正式な公開URLへ差し替えてください。

法律事務所のローカルサーバーでも、この相互リンクを確認できます（更新後はサーバーを再起動してください）。読み出す塾側のファイルは現行４ページと必要な画像・CSS・JavaScriptに限定し、アーカイブや作業用ファイルは配信しません。

## サーバーにつながないテスト（今回の使い方）

1. このフォルダーの `index.html` をChromeまたはEdgeで直接開きます。アドレスが `file:///` で始まる状態です。
2. トップの４つの取扱分野から、それぞれの詳細ページへ移動できます。
3. ページ下部の「管理者ログイン」から `admin.html` を開き、パスワード **TWIY**（半角・大文字）で入ります。初回設定やユーザー名は不要です。
4. 「取扱分野の記事」で分野を選び、文章を編集します。「仕上がりを確認」は保存前のプレビュー、「この記事を保存して反映」で保存します。
5. 詳細ページやトップページを開き直すと、保存した文章が反映されます。「料金・アクセス」も同じ管理画面から編集できます。

見出し、冒頭のメッセージ、本文、お悩み、対応内容、相談の進め方、質問と回答、問い合わせへの案内を編集できます。対応内容・質問は項目の追加と削除もできます。未保存の記事を切り替える際は確認を表示します。

### テストデータの保存先と注意点

編集内容は**同じブラウザー・同じフォルダー用の保存領域**に保存されます。ページ間で共有するため `demo-store.html` を使います。このファイルも含めて同じフォルダーに置いてください。HTMLの原本自体を書き換える機能ではありません。別の端末・ブラウザーには自動で反映されず、ブラウザーのデータ削除やプライベート閲覧の終了で失われる場合があります。

管理画面の「記事のバックアップ・読み込み」で、保存済みの４分野の記事をJSONファイルに書き出せます。読み込みは選択中の分野の編集欄に反映するだけなので、内容を確認して保存してください。料金・住所の設定は記事バックアップには含まれません。

この簡易パスワードは**ローカルで画面と操作を試すためのもの**で、本番公開用の認証ではありません。実際の個人情報や機密情報は登録しないでください。問い合わせフォームは入力と内容確認までで、送信は行いません。テスト版ではメール設定・問い合わせ一覧は表示しません。

テスト機能は `file:///` で開いたときに限られます。サーバーのURLで開いた場合は、以下の従来の安全な認証と保存方式になります。既存のサーバー側の管理者設定・データは変更していません。

## ブログの使い方

サイト上部・下部の「ブログ」から `blog.html` の記事一覧へ移動します。最初は記事がない状態です。架空の事例や事務所の写真は掲載していません。

一覧は新しい掲載日から１ページ９件。カテゴリ、タイトル・本文のキーワード検索、ページ送りで探せます。スマートフォンでは１列になり、写真がない記事も同じカード形式で整います。個別記事は `blog-post.html?id=記事番号` で表示し、見出しが２つ以上ある場合は目次、同じカテゴリにほかの記事がある場合は関連記事を表示します。

### 記事と写真の編集

1. 管理者画面で「ブログ」→「新しい記事を書く」を選びます。ローカルテストのパスワードは引き続き **TWIY** です。
2. タイトル、カテゴリ、掲載日、一覧の紹介文を入力します。カテゴリは自由に追加できます。掲載日は表示・並び順のためのもので、未来の日付による予約掲載ではありません。
3. 必要に応じてアイキャッチ写真を選び、本文に「段落」「見出し」「写真」を追加します。「上へ」「下へ」で並べ替えられます。
4. 「仕上がりを確認」でプレビューし、「下書き保存」または「掲載して保存」を選びます。下書きは一覧にも直接の記事URLにも表示されません。
5. 保存済みの記事は一覧の「編集する」から更新できます。「ごみ箱へ」は非表示にする操作で、状態を「ごみ箱」に切り替えると下書きへ戻せます。完全削除は行いません。

写真はJPEG・PNG・WebP（選択前15MB以内）、１記事８枚までです。表示用に長辺最大1600px、一覧用に480pxへ縮小して保存し、写真に含まれる位置情報等のメタデータは引き継ぎません。元の写真はご自身で保管してください。写真の読み上げ用説明は掲載時に必須、写真下のキャプションは任意です。

### ブログの保存とバックアップ

ローカルテストでは、写真の容量を考慮してブログをブラウザーの **IndexedDB** に保存します。従来の取扱分野・料金・アクセスの保存領域とは分けています。`demo-store.html` を含む同じフォルダー・同じブラウザーで確認してください。「掲載して保存」してもインターネット上には公開されず、別の端末には自動で移りません。ブラウザーのデータ削除等で失われるため、定期的にバックアップしてください。

記事編集画面の「画像付きバックアップ」で、その記事の入力中の文章と写真を１つのJSONファイルに書き出せます。一覧下部の「バックアップを読み込む」は、新しい下書きとして取り込みます。既存の記事は上書きせず、内容確認後の保存が必要です。ブログのバックアップは１記事単位で、従来の４分野の記事バックアップとは別です。

サーバーを利用する場合は、ブログ記事・画像も `.data/site.sqlite` に保存し、従来どおり認証された管理者だけが編集できます。ローカルテストのブラウザー保存データはサーバーへ自動移行されません。写真付きバックアップを読み込み、確認後に掲載してください。

## サーバー利用時の起動と管理者の初回設定

Node.js 22.13以降を使用します。依存ライブラリは `pnpm install`、起動は `node server.mjs` です。

1. 起動後、`http://127.0.0.1:8787` を開きます。
2. 初回のみ、起動メッセージに表示される「初回管理者設定」のリンクを開きます。
3. 自分で決めた14文字以上のパスワードを登録します。初期パスワードはありません。
4. 次回からはページ下部の「管理者ログイン」を使います。

サーバー利用時は、起動したサーバーのURLからアクセスしてください。初回設定リンクは他の人と共有しないでください。簡易パスワード「TWIY」はサーバー側では使用できません。

## 編集できる情報

- ４分野の詳細記事（見出し・本文・相談例・対応内容・質問と回答など）
- ブログ記事（タイトル・カテゴリ・掲載日・紹介文・本文・写真・掲載／下書き状態）
- 相談料・着手金・報酬金・実費・顧問料と料金ページの案内文
- 住所・最寄り駅と道順・営業時間・Googleマップへのリンク・ご来所の案内文
- フォームの受付開始／停止
- 非公開の受信メールアドレス、送信元、SMTP設定

保存すると、各ページを次に開くか再読み込みしたときに反映されます。初期状態は「受付停止」です。

## メールフォーム

入力 → 内容確認 → 送信の順に進みます。受付が有効な場合、問い合わせをサーバーのデータベースに保存します。メール通知には、契約しているメールサービスのSMTPホスト、ポート（465または587）、ユーザー名、パスワード、送信元アドレス、および受信先を設定してください。

メール未設定でも問い合わせは管理画面で確認できます。通知に失敗しても保存済み内容は失われず、一覧に通知状態を表示します。一覧は最新100件です。SMTPパスワードは空欄で保存すると保持されます。変更時のみ新しい値を入力してください。

## データと公開時の設定

管理者情報、掲載内容、問い合わせは `.data/site.sqlite` に保存します。SMTPパスワードの復号鍵は `.data/mail-key` です。バックアップはサーバーを停止して `.data` フォルダ全体を保管してください。`.data` は公開・Git登録しないでください。

外部公開にはNode.jsを常時稼働できるサーバーと永続ディスクが必要です。静的HTMLだけのホスティングでは管理機能・送信機能は動作しません。HTTPSの前段サーバーを設置し、`PUBLIC_ORIGIN=https://実際のドメイン` を指定してください。必要に応じて `HOST` と `PORT` を設定します。プロキシはCookie・Originをそのまま渡してください。

初回設定を済ませ、正しい住所・料金・メール設定を保存してから公開してください。メールの実配信は未定の設定情報が揃ってから確認します。この作業では外部公開も実メールの送信も行っていません。

## 検証

`npm test` で認証、権限制御、記事と設定の保存、入力検証、ページのリンク、フォーム受付を確認します。ブログは下書きと画像の非公開、競合防止、写真との一括保存、ごみ箱からの復元、サーバー再起動後の保持も検証します。テストは一時データベースと模擬メール送信を使用し、既存データと外部メールには触れません。

ブラウザー検証は `TWIY_PLAYWRIGHT` にPlaywrightパッケージのパス、`TWIY_CHROME` にChrome実行ファイルのパスを指定し、`npm run test:browser` を実行します。環境変数が未設定ならスキップします。独立したテスト用ブラウザーで、簡易ログイン、別ファイルへの記事反映、保存前プレビュー、バックアップ、スマートフォン表示を確認します。ブログでは写真の追加・縮小、目次、検索、21件の記事のページ送り、画像付きバックアップの再取り込みも検証します。
